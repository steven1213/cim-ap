## 2. 用户动线与断点分析

### 动线 A：发起人
```
选模板 → 填表单(带schema/附件) → 提交 → 我发起的(跟踪) → 催办/撤回 → 收到结果(回调)
                                  ✅        ✅              ✅ 本期补齐     ✅
断点：提交后"只能等"——催办/撤回补齐后动线闭环。剩余缺口：草稿箱(P1)、抄送(P2)。
```

### 动线 B：审批人
```
收到通知(SSE铃铛) → 我的待办 → 详情(内容/附件/历史) → 通过/驳回/回退/加签/改派 → 已办
        ✅             ✅            ✅                     ✅                  ✅
断点：通知仅实时弹窗，离线无提醒——超时提醒(P1)兜底；多人共担需候选人组(P2，依赖 IAM)。
```

### 动线 C：管理员
```
设计器画流程 → 部署 → 注册回调 → 监控运行 → 审计追溯
     ✅          ✅       ✅         ⚠️弱         ✅
断点：监控只有工作台 KPI，缺效率分析(P1 统计报表)与实例卡点告警(P2)。
```

## 3. 缺口清单（分级）

### P0 —— 动线闭环，本期已落地 ✅
| 项 | 说明 |
|---|---|
| 分级菜单导航 | 侧边栏按「工作台/审批中心/流程配置/合规治理」四组分层，不再平铺 |
| 撤回 | 发起人终止运行中实例：仅发起人可操作、WITHDRAW 审计入哈希链、回调 result=WITHDRAW、列表/详情展示「已撤回」 |
| 催办 | 发起人向当前待办人/候选人推 SSE 实时提醒（铃铛 toast + 角标），URGE 审计入链 |

### P1 —— 效率与体验（已落地三项 ✅）
| 项 | 说明 | 状态 |
|---|---|---|
| 超时提醒 | 任务停留超阈值（`approval.task.timeout-minutes`，默认 24h）→ `OverdueScanner` 定时扫描推 SSE（TASK_OVERDUE，每任务一次）+ 待办/我发起的列表标红「已超时 N」 | ✅ |
| 待办筛选/搜索 | 待办/已办/我发起的右上角关键字过滤（标题/业务单号/节点名），客户端过滤 | ✅ |
| 草稿箱 | 发起表单自动暂存 localStorage（含业务表单行），重开自动恢复 + 可放弃；提交后清除 | ✅ |
| 统计报表 | 审批效率分析：平均处理时长、驳回率、各定义/审批人工作量 TOP、近 30 天趋势；工作台增强或独立页 | ❌ |
| 委托代理 | 审批人休假期间委托他人代审；代理链路记审计 | ❌ |

### P2 —— 平台化与规模化
| 项 | 说明 | 依赖 |
|---|---|---|
| 抄送 | 节点配置抄送人，「抄送我的」列表 | 无 |
| 候选人组 | candidateGroups + IAM 用户组解析 | IAM 组体系 |
| 附件对象存储 | 本地磁盘 → MinIO/S3，多实例共享 | 存储设施 |
| 定义级租户隔离 | 部署携带 tenantId，多业务系统模板物理隔离 | 租户方案细化 |
| 实例监控告警 | 卡点实例识别（同节点停留过长）+ 告警 | 统计报表 |
| 数据归档 | 历史实例/审计冷数据归档，控制库膨胀 | 无 |

## 4. 实现摘要

### P0（动线闭环）
- **后端**：`POST /processes/instances/{id}/withdraw?actor=`、`POST /processes/instances/{id}/urge?actor=`；
  撤回 = 发起人校验 + `deleteProcessInstance(deleteReason=WITHDRAW)` + 审计 + 回调；催办 = 发起人校验 + 向任务办理人/候选人 SSE 推送 + 审计。
  `WITHDRAWN` 状态经 `HistoricProcessInstance.getDeleteReason()` 映射（列表/详情一致）。
- **前端**：我发起的 → 运行中行出现「催办/撤回」（撤回有确认弹窗）；铃铛识别 URGE 事件（warn toast + 角标）；
  详情时间线新增 催办/撤回 动作标签；菜单四级分组。
- **回归脚本**：`web/scripts/verify-journey.mjs`（催办审计 + 撤回状态 + 菜单分组断言，11 项）。

### P1（效率与体验）
- **后端**：`TaskView/ProcessInstanceView` 增加 `overdueMinutes`（Double 小数分钟）；
  `OverdueScanner`（`@Scheduled`，阈值 `approval.task.timeout-minutes` 支持小数、间隔/首扫可配）超时任务向办理人/候选人推一次 `TASK_OVERDUE` SSE（内存去重）。
- **前端**：待办/我发起的超时红色标签（`fmtOverdue` 人性化 min/h/d）；三列表关键字过滤（`search-inline`）；
  发起弹窗草稿自动暂存/恢复/放弃（`approval.draft.v1`）；铃铛识别 TASK_OVERDUE。
- **回归脚本**：`web/scripts/verify-p1.mjs`（10 项：API overdueMinutes + UI 标红/过滤/草稿恢复）。
  ⚠️ 脚本依赖短阈值启动：`--approval.task.timeout-minutes=0.05 --approval.task.scan-interval-ms=5000 --approval.task.scan-initial-delay-ms=3000`。

## 5. 决策记录

1. 撤回**不设审批中拦截**（如"已审批一票不可撤"）——首版从简，业务若有此诉求再加 `withdrawPolicy`。
2. 催办**只推实时通道**（SSE），不落库为独立通知实体——与 NEW_TASK 同级；离线补偿由 P1 超时提醒兜底。
3. WITHDRAWN 复用 `deleteReason` 而非新增业务字段——Flowable 历史天然携带，零迁移成本。
4. 超时阈值**实例级统一**（单配置键，支持小数分钟）而非按节点配置——首版从简，节点级差异化留待按需扩展。
5. 超时 SSE 每任务**只推一次**（内存去重）——避免重复打扰；多实例部署需换分布式去重。
6. 草稿箱选 **localStorage 单草稿**（全平台一份，按最后编辑保存）——零后端成本；多草稿/服务端草稿为后续增强。
