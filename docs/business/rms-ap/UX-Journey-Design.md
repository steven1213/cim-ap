# RMS 动线设计与使用流程（UX Journey Design）

> 版本：2026-10-13 · 适用：cim-ap / rms-ap（W7 后 + P1/P2/P3 动线重组后）
> 依据：Req.md（D1–D9、FR/IF 条款）+ 行业调研（camLine LineWorks RM、AMAT SmartFactory、SYSTEMA、SEMI E42/E139）+ 角色×任务走查

---

## 1. 设计原则（本轮确立）

| 原则 | 含义 | 落地 |
|---|---|---|
| 一处搞定 | 一个实体的生命周期动作全部在该实体的详情里完成 | 机台详情抽屉 / 配方详情抽屉两个枢纽 |
| 任务驱动 | 进系统第一屏回答「现在有什么要处理」 | 概览页 = 任务中心（待批签核/漂移/孤儿/报警/放行） |
| 一次定位 | 同一配方/机台不跨页重复定位 | 抽屉互斥联动：机台 ↔ 配方来回切换 |
| 频率分层 | 高频日常在上，低频基础数据收尾 | 菜单三组：日常作业 / 治理与合规 / 基础数据 |
| 状态约束 | 状态机决定可做什么，UI 只是不给它出现 | DRAFT 可编辑/可签核；ACTIVE 只读+另存新版本 |

## 2. 角色与动线设计（核心交付）

### 2.1 角色 → 入口映射

| 角色 | 高频任务 | 首选入口 |
|---|---|---|
| 工艺工程师 | 建配方/改配方/发签核/看装载 | 概览 → 配方库 → 配方详情抽屉 |
| 工艺/设备主管 | 批签核/盯异常/盯漂移 | 概览任务中心（第一屏即行动项） |
| 设备工程师 | 接机/绑配方/看腔体/比对 | 设备配方（区域树）或机台详情抽屉 |
| 质量/QA | 审计/签核证据/Golden 治理 | 治理与合规组（审计/签核/Golden） |
| 系统管理员 | 机型/区域/模板/授权/EC-SV | 基础数据组（低频维护） |

### 2.2 动线一：新配方上线（全生命周期闭环）

```
配方库「新建配方」（Body + 格式）
   └─ 自动解析 → 参数快照（JSON_STRUCTURED / TEXT）
配方详情抽屉（打开即见）
   ├─ 规格参数区块：就地增删改规格（TARGET/RANGE/LIST_IN/TOLERANCE）
   ├─ 校验：良构 ✓ 可执行 ✓（规格越界实时标红）
   ├─ 编辑 Body（仅 DRAFT）→ 重算 hash → 重解析
   └─ 「发起签核」（就地弹窗：原因 + 签核路由 SINGLE/COUNTERSIGN/ANY）
签核页（审批人）：批准 → 后端自动激活（旧 ACTIVE 退位 OBSOLETE）
   └─ 也可在配方库对 DRAFT 手动激活
集成监控：下发（QUEUED→GRANTED→SENT_TO_TOOL→TOOL_ACKED→VERIFIED）
   └─ 回读 bodyHash 验证；漂移判 FAILED + RMS_DRIFT 报警
机台验证：巡检 reconcile（OK/DRIFT/ORPHAN）→ 异常进概览任务中心
```

**闭环关键点**：批准自动激活；VERIFIED 以回读 hash 为准；孤儿（机台有、RMS 无）与死映射（映射指向已删配方）都计入孤儿可见——「机台上跑的」与「RMS 认为的」永不静默分叉。

### 2.3 动线二：改一版已生效配方（迭代闭环）

```
概览任务中心 或 配方库 → 打开配方详情抽屉
   └─ 切到 ACTIVE 版本（只读）→「另存新版本」
        └─ 以当前内容 + 旧 hash 乐观锁建新 DRAFT，抽屉自动切到新版本
             └─ 编辑 Body → 规格调整 → 发起签核 → 批准自动激活（旧版退位）
```

**闭环关键点**：ACTIVE 不可变 + 另存即迭代；compare 页可对任意两版本/两配方做 FULL_BODY/PARAMETER/STRUCTURE 比对，diff 自动生成。

### 2.4 动线三：给机台装载配方（双向枢纽）

```
正向（机台视角）：设备台账点行 → 机台详情抽屉
   ├─ 基本信息 + 腔体管理（就地增删改，删除有 PPID 引用守卫）
   ├─ 绑定配方：PPID + 配方（+ 可选腔体）→ 一处完成
   └─ 装载列表（四来源聚合：TYPE_APPLICABLE∪PPID_MAPPED∪QUALIFIED∪ON_TOOL）
        └─ 行内解绑 / 点配方行 → 切配方详情抽屉（关闭自动回机台）
反向（配方视角）：配方详情抽屉「装载机台」区块
   └─ 反查被谁装载（含腔体与资格状态）+ 绑定表单（机台→腔体联动）
```

### 2.5 动线四：工厂 → 区域 → 机台 → 配方（空间动线，2026-10-13 补）

```
设备配方页（空间一条线，工程师/主管找「某台机器上跑的是什么」）
   左树：顶层节点=工厂（FAB 徽标）→ 子层=区域 → 机台（叶子）
        └─ 点机台 → 自动展开祖先链 + 右侧面包屑同步
   右侧：面包屑 一厂 / 刻蚀区 / EQ-01（点任一层级跳回树中位置）
        ├─ KPI（总量/孤儿/漂移/未资格）
        ├─ 配方表（四来源聚合，含腔体 PPID）→ 点行 → 配方详情抽屉
        └─ 抽屉内可直接签核/另存/导出（复用动线一/二能力）
入口配套：区域管理页父级下拉显式标注「顶层（= 工厂）」，数据模型零改动
   （device_area 自引用树，parent=null 顶层即工厂；演示数据 FAB1 → ETCH/FILM 已就位）
```

### 2.6 动线五：异常处理（主管日常）

```
概览任务中心（第一屏）
   ├─ 待批签核 n 条 → 点击直达签核审批队列
   ├─ 机台配方漂移 n 条 → 点击直达设备配方（区域树定位机台）
   ├─ 孤儿配方 n 条 → 同上（未纳管 = 绕过变更管控，必须清零）
   ├─ 未确认报警 → 直达集成监控（老问题不重复刷屏）
   └─ 临时放行中/即将到期 → 直达签核页（预约限时自动失效）
```

### 2.7 动线六：实验/低频（治理兜底）

- **Bypass / 设备授权 / EC-SV**：基础数据组，接机与调试场景
- **Golden 治理**：Golden 配方改动走同一条签核链；Golden 覆盖在治理组
- **审计**：全操作链（谁/何时/对哪个配方做了什么），QA 可回溯

## 3. 行业对齐结论（本轮调研）

对标 **camLine LineWorks RM**（行业事实标杆）、SYSTEMA、SEMI E42/E139、AMAT SmartFactory：

| 行业能力 | camLine/业界做法 | RMS 现状 | 结论 |
|---|---|---|---|
| 集中存储+版本树 | 单一事实源、全版本历史 | ✅ RecipeVersion + sourceVersionId 血缘 | **对齐** |
| 多级审批流（APM） | 审批板+可执行工作流+实时通知 | ✅ SINGLE/COUNTERSIGN/ANY + eSignHash 证据链；❌ 无实时通知 | **对齐（通知待补）** |
| 配方 Body 结构解析（ROSI） | 解码+图形化+SMART COMPARE | ✅ JSON/TEXT 解析器+参数/步序/子配方视图；❌ 无自定义格式解析器注册 UI | 基本对齐 |
| 参数限值控制 | 默认限值+运行时比对规则 | ✅ ParamSpec 四类+executable 校验；❌ 限值未联动设备端强制 | 部分对齐 |
| 上下文解析（Context Resolution） | Operation+Equipment+Product 自动选配方 | ✅ 四来源聚合+PPID/腔体维度；❌ 无产品/批次上下文 | 部分对齐（依赖 MES 集成深度） |
| 自动验证（Auto Validation） | 发布前强制校验 | ✅ 良构+可执行；签核页提示 diff 自动生成 | **对齐** |
| 运行时比对（Runtime Compare） | 生产中持续比对 | ✅ 巡检 reconcile（OK/DRIFT/ORPHAN）+ GEM 事件双轨 | **对齐** |
| Recipe Hold（Stop the presses） | 按耗材/维护批量 Hold 配方 | ✅ Hold 机制存在；❌ 无「按条件批量 Hold」 | 部分对齐 |
| 另存/回滚 | 分支+一键回滚 | ✅ 另存新版本（本轮补 UI 闭环）；回滚=对旧版本另存+走签核 | **对齐**（Git 式分支超出 RMS 惯例，业界也不做） |
| 导入/导出 | 配方文件级备份/迁移 | ❌ 无 | **缺口**（生产化必补，见 §5） |
| 变更效果跟踪 | 变更前后 Cpk/SPC 对比 | ❌ 属 SPC 域，RMS 提供变更记录挂钩 | 边界外（接口预留） |

## 4. 功能全景与闭环判定

### 4.1 已闭环（可用链）

1. **配方生命周期**：建 → 解析 → 规格 → 校验 → 签核 → 批准自动激活 → 旧版退位 → 另存迭代 ✅
2. **下发验证链**：下发阶段机 → 回读 hash → VERIFIED / FAILED+RMS_DRIFT ✅
3. **机台一致性**：巡检 reconcile + GEM 事件双轨 → DRIFT/ORPHAN 可见可处理 ✅
4. **装载治理**：绑定/解绑双向 + 腔体维度 + 引用守卫（删配方查映射、删腔体查 PPID）✅
5. **安全链**：JWT 准入 → 幂等（scope+idemKey）→ 签核证据链（eSignHash）→ 审计 ✅

### 4.2 未闭环 / 生产化缺口（按风险排序）

| # | 缺口 | 生产风险 | 建议优先级 |
|---|---|---|---|
| 1 | **配方导入/导出**（文件级备份、灾备迁移、跨厂复制） | 数据只进不出，灾备无从谈起 | P0 |
| 2 | **批量操作**（批量下发/批量 Hold/批量绑定） | 一次气体事件要手动处理上百条 | P1 |
| 3 | **审批实时通知**（站内信/邮件/企微） | 审批靠人刷任务中心，积压风险 | P1 |
| 4 | **D9 Body 加密**（Req 明确要求，未做） | 敏感工艺参数（IP）明文存储 | P1 |
| 5 | 配方 Body 模板（强制键/默认值，camLine ROBDEF） | 新配方结构靠自觉，解析失败率高 | P2 |
| 6 | 实验路径（DOE 临时配方受控通道） | 工程师绕过 RMS 直改机台 | P2 |
| 7 | 变更效果跟踪挂钩（记录→SPC 查询引用） | 变更后效果靠人肉回忆 | P2（跨域） |
| 8 | 自定义解析器扩展点（E42 派生格式） | 遇专机格式需改代码发版 | P3 |
| 9 | 机台侧限值强制（设备端参数越界硬停） | 限值只在 RMS 校验，设备端裸奔 | P3（需 EAP 联动） |

### 4.3 生产环境就绪判定

- **功能面**：核心闭环已达成，可支撑单厂单域试运行；
- **上量产前必须补**：#1 导入导出、#4 D9 加密、#2 批量 Hold（三项为硬门槛）；
- **可带病运行**：#3 通知（先用任务中心顶）、#5–#9 按迭代排。
