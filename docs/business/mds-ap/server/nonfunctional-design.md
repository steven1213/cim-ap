# MDS 非功能设计（容量 / 性能 / 可用性 / 迁移 / 并发 / 可观测性）

> 本文补齐 MDS 的**非功能性设计**——此前 36 篇文档全部聚焦"数据结构与语义"，**未定义容量、性能指标、可用性目标、迁移与初始化方案、并发策略、可观测性**。
>
> 对 MES 而言这些不是"锦上添花"：MDS 是**生产依赖的主数据源**，其性能与可用性直接决定产线节拍与停线风险。
>
> 设计原则延续全篇：**热路径本地缓存零回查；MDS 不可用不影响产线连续运行**。

## 1. 容量与数据量估算

### 1.1 按表类别分档

| 档 | 类别 | 典型表 | 单租户量级 | 归档策略 |
| --- | --- | --- | --- | --- |
| **A** | 定义/参考数据（码表、单位、参数、枚举、类型） | `mds_uom` `mds_code_table_item` `mds_param_def` `mds_*.class/type/model` | 10³–10⁴ | 不归档 |
| **B** | 主数据（位置、设备、产品、路线、配方、资产） | `mds_location` `mds_equipment` `mds_product` `mds_route` `mds_recipe` `mds_reticle` `mds_tooling` | 10³–10⁵ | 不归档 |
| **C** | **关系/映射表**（数量最大的一类） | `mds_equipment_recipe_qual` `mds_carrier_type_compat` `mds_material_bom_line` `mds_layer_operation` `mds_constraint_binding` `mds_document_link` `mds_route_flow` | 10⁴–10⁶ | 按失效时间归档 |
| **D** | **历史表**（`@History(SNAPSHOT)` 自动生成） | `mds_*_hist` | **10⁶–10⁷** | **按时间分区，≥ 2 年归档** |
| **E** | 分发与试算结果 | `mds_md_release_item` `mds_md_delivery` `mds_process_flow_compare_item` `mds_constraint_eval_item` | 10⁵–10⁶ | **≥ 1 年归档**（保留头表） |

> **关键结论**：**历史表（D）与分发表（E）是容量主体**，必须设计归档与分区；A/B/C 三类即使全量常驻也完全可接受。

### 1.2 单 fab 估算示例（供容量规划参考）

| 输入假设 | 值 |
| --- | --- |
| 设备 | 2,000 台（含模块/端口 → ×10 行 ≈ 2×10⁴） |
| 位置节点 | 3,000 |
| 产品 / 配方 / 路线 | 500 / 8,000 / 300 |
| 光罩 / 测试资产 / 工装 | 2,000 / 1,500 / 5,000 |
| 物料 | 20,000 |
| 配方资格（设备 × 配方） | ≈ **2×10⁵**（设备 × 平均合格配方数） |
| 路线工序 / 工艺流步骤 / 参数 | 300×80 / ×1.5 / 参数 ×5 ≈ 3×10⁵ |
| 约束绑定 | ≈ 2×10⁴ |
| **B+C 合计** | **≈ 10⁶ 行** |
| 历史表（按主数据年变更 3 次） | **≈ 3×10⁶ 行/年** |

> 结论：**单 fab 十年数据约 3×10⁷ 行**，对现代关系库（分区 + 归档）完全可控；但**不做归档会在 3–5 年内成为运维负担**。

### 1.3 归档策略原则

| 对象 | 策略 |
| --- | --- |
| `_hist` 历史表 | 按 `op_time` 月分区；> 2 年移冷存储（保留可查接口） |
| `mds_md_release_item` | > 1 年归档；`mds_md_release` 头表长期保留（版本可溯） |
| 试算/对比明细（`*_compare_item` `*_eval_item`） | > 1 年归档；头表保留（评审留痕） |
| 签名 `mds_md_signature` | **永不归档**（合规要求，见 [md-governance 附录 A](md-governance-design.md)） |
| 软删数据 | 保留但移出热表（`deleted=1` 分区隔离） |

## 2. 性能设计

### 2.1 目标指标

| 类别 | 接口/场景 | 目标 | 保障手段 |
| --- | --- | --- | --- |
| **热路径** | 组批/派工/搬运/上机/判异/判定 | **≤ 50 ms** | **本地缓存 + 规则包求值，零 MDS 回查**（[realtime-contract §7](realtime-contract-design.md)） |
| 解析接口 | `resolve-*`（PPID/合格设备/合格光罩/生效模型…） | ≤ 300 ms | 收敛为单次查询 + 结果缓存 + 接入期预热 |
| 管理端列表 | 各域分页查询 | ≤ 500 ms | 覆盖索引 + 游标分页 |
| 管理端详情 | 单实体 + `include` 关联 | ≤ 300 ms | 显式 `include` 控制嵌套，禁默认全展开 |
| 低频查询 | 追溯类（BOM 展开 / 血缘） | ≤ 2 s | 递归展开缓存 + 限制深度 |
| 写入 | 单条保存 | ≤ 200 ms | 乐观锁 + 短事务 |
| 批量 | 种子/迁移导入 | 10⁴ 行/分钟级 | 批提交（`batch_size` 可调）+ 关闭逐行事件 |

### 2.2 索引策略（统一约定）

| 索引对象 | 说明 |
| --- | --- |
| 唯一键 | 一律 `(..., tenant_id, deleted)`（T2.5），天然覆盖租户+软删过滤 |
| 外键列 | 所有 FK 列建索引（聚合查询与级联校验都需要） |
| **状态列** | `status` / `admin_status` / `lifecycle_status` 建索引（列表筛选高频） |
| **作用域列** | `scope_type` + `scope_ref`、`domain_code`、`entity_type` + `entity_ref` 建复合索引 |
| 时间列 | `effective_from/to`、`op_time`（分区键）、`next_due_at` 建索引 |
| 反模式 | ❌ 对 `ext_attrs`/`override_json` 等 JSON 列做业务查询（应为查询维度显式建列） |

### 2.3 缓存层次

```
L1 本地缓存（Caffeine，TTL 秒级）    ← 字典/码表/参数/生效规则（热路径求值依赖）
L2 分布式缓存（Redis，TTL 分钟级）   ← 解析接口结果、列表查询
L3 规则包 / 快照（版本化，长 TTL）   ← 约束/处置/SPC 规则、点表、生效主数据（下游本地）
```

- **失效策略**：以 `release.version` 为准，版本变更即失效（[md-distribution §4.3](md-distribution-design.md)）；
- **预热**：接入期批量预热 `resolve-*` 结果，避免运行期首次调用抖动。

### 2.4 关键的 N+1 与热点

| 风险 | 处理 |
| --- | --- |
| 列表默认展开关联 | `include` 显式声明；默认不展开 |
| 参数窗口逐 step 查询 | 按 `step_id` 批量 `IN` 查询 |
| **命名序列热点**（`mds_naming_seq` 单行自增） | **分段号池**：每次取 N 个号在内存分配，降低行锁争用 |
| 约束求值重复解析 DSL | AST 缓存（按表达式哈希） |
| 双向引用校验逐条查库 | 批量存在性校验（`IN` + 结果集比对） |

## 3. 可用性与容灾

### 3.1 设计底线（最重要）

> **MDS 不可用不得导致产线停线。** 下游（MES/EAP/AMHS）以最后一份快照继续生产，进入**降级运行**并告警（[realtime-contract §6](realtime-contract-design.md)）。
>
> 例外：需要**新主数据**的操作（新产品首投、新配方首用）无法降级 → 挂起或走应急审批。

### 3.2 目标与手段

| 项 | 目标/手段 |
| --- | --- |
| RPO（数据丢失容忍） | **≤ 5 min**（依赖数据库 binlog 持续归档） |
| RTO（恢复时间） | **≤ 30 min**（主从切换 + 服务重启） |
| 服务形态 | **无状态多实例** + 负载均衡（会话无状态，租户由 Token 承载） |
| 数据库 | 主从（读写分离可选）；只读查询走从库（缓存未命中时） |
| 单点 | 命名序列（分段号池）；缓存（降级为直连库） |
| 备份 | 全量（每日）+ 增量（binlog）；**每季度恢复演练** |
| 发布 | 灰度（先非生产租户/站点），支持快速回滚（迁移可逆或前向修复） |
| 分区/多站点 | 多 fab 可独立部署实例（[multi-site](multi-site-design.md) 的 scope 订阅天然支持） |

### 3.3 降级分级

| 级别 | 触发 | 行为 |
| --- | --- | --- |
| L0 正常 | — | 全部功能可用 |
| L1 部分降级 | 从库/缓存异常 | 只读走主库；管理端变慢，**生产不受影响** |
| L2 写降级 | 主库写异常 | **禁写**（主数据变更挂起），读与下发继续 |
| L3 MDS 不可用 | 服务不可达 | 下游用最后快照生产；新主数据操作挂起 + 告警 |

## 4. 数据迁移与初始化

### 4.1 顺序依赖（必须遵守）

```
L0 基础参考数据（单位 → 码表 → 参数定义）
   ↓
L1 空间与组织（位置 → 组织/供应商 → 工作日历/班次）
   ↓
L2 资产（设备型号 → 设备/模块/端口 → 设备能力 → 点表 → 载具 → 光罩/测试资产/工装 → 仓库 → 厂务 → PMC）
   ↓
L3 工艺定义（产品族 → 产品 → 层 → 工序规范 → 路线 → 工序/边 → 逻辑配方 → 物理配方 → 工艺流 → 配方资格）
   ↓
L4 物料与产出（物料 → 物料规格/寿命策略 → 用料BOM → 产品结构BOM → 批次类型）
   ↓
L5 运维与质量（PM/校准 → 原因码 → 缺陷/Bin → 处置规则 → 采样/SPC/OCAP → 洁净度/环境 → APC/FDC）
   ↓
横切（命名规则 → 约束 → 表达式注册表 → 域注册/责任人/工作流 → 订阅）
```

**三条铁律**：① 先字典后主数据；② 先定义后关系（FK 目标必须先存在）；③ 先校验后入库。

### 4.2 迁移步骤

| 步骤 | 内容 | 产出 |
| --- | --- | --- |
| 1 盘点与清洗 | 存量主数据盘点、去重、编码规范对齐（[naming-rule](naming-rule-design.md)） | 清洗后数据集 |
| 2 映射 | 旧字段 → MDS 字段；**`param_name` → `param_def` 映射**（[99-backlog T4-1](99-backlog.md)） | 映射表 |
| 3 试迁移 | 在影子库执行，跑 [md-governance](md-governance-design.md) 质量规则 | 校验报告 |
| 4 修正 | 处理校验失败项（引用缺失/唯一冲突/格式） | 通过率 ≥ 99% |
| 5 正式迁移 | 按 §4.1 顺序分批；每批记录为一笔 `mds_md_release`（可溯） | 发布批次 |
| 6 切换 | 下游订阅切至 MDS（双跑/影子读过渡期） | 切流记录 |
| 7 回滚预案 | 迁移按批次可回退；回退前冻结写入 | 回滚脚本 |

### 4.3 初始化种子清单

种子数据（各域 §5-6 已列）统一登记在 [99-backlog T4-3](99-backlog.md)：码表、SI 单位、核心参数、E10 停机原因、常见缺陷码、班次/日历、WE/Nelson 规则集、域注册、审批工作流、GEM 必备 SV/CEID/ALID。

## 5. 并发与一致性

| 场景 | 策略 |
| --- | --- |
| 单实体并发更新 | 乐观锁 `@Version` + `If-Match`；冲突返回 `409` + 最新版本，客户端重试（**指数退避**） |
| **命名序列（`mds_naming_seq`）** | 分段号池（内存预取 N 个）+ 乐观锁兜底；流水**永不回退** |
| 版本克隆（`cloneAsNewVersion`） | 单事务内完成（头 + 子表 + 关系表）；批量克隆串行化，避免编号争用 |
| 约束/绑定/映射类多写 | 后写覆盖 + `@History` 留痕（不阻塞）；关键类（如资格）可加悲观锁 |
| 分发一致性 | 发布批次**原子生成**（头 + item 同事务）；下游按幂等键应用；回执超时重试（[md-distribution §4.4](md-distribution-design.md)） |
| 试算/对比并发 | 互不阻塞（结果落独立批次表），允许并行 |
| 跨域事务 | **不做分布式事务**；用"本地事务 + 最终一致（分发）"保证跨系统一致 |

## 6. 安全（非功能侧）

| 项 | 约定 |
| --- | --- |
| 限流 | 按消费者 + 接口分级；**订阅通道不占用热路径配额**（[api-design §4](api-design.md)） |
| 防重放 | 写接口 `Idempotency-Key` |
| 越权放行 | `SOFT` 约束放行须留痕并可审计 |
| 批量接口 | 仅限管理员角色 + 操作留痕 + 速率上限 |
| 导出/下载 | 大结果集走异步任务 + 一次性令牌 |

## 7. 可观测性

| 维度 | 内容 |
| --- | --- |
| **指标** | QPS、P50/P95/P99 延迟（按接口分级）、错误率（按 `BizCode` 段）、缓存命中率、**订阅滞后**、**未 ACK 批次**、**降级运行标记**、回写失败率、序列池剩余 |
| 日志 | 结构化 JSON + `traceId`；写操作记录操作者与来源 |
| 追踪 | `traceId` 从 MES 透传至 MDS（跨系统调用链）；慢查询采样 |
| 告警 | ① 热路径延迟超阈；② 订阅滞后 > 阈值；③ `mds_md_delivery` 出现 `NACK`/`EXPIRED`；④ 白名单回写连续失败；⑤ 质量规则校验失败率上升；⑥ 归档任务失败 |
| 大盘 | 「主数据健康度」：域覆盖、发布批次、下游版本分布、质量规则通过率 |

## 8. 与 MES 衔接的容量与性能含义

| 关注点 | 结论 |
| --- | --- |
| 派工节拍 | 受 MDS 影响的只有**缓存刷新**（分钟级）与**受限操作**（新主数据），**不受 MDS 在线性能影响** |
| 网络依赖 | 热路径**无网络依赖**（规则包本地）；仅事件驱动路径需连通 |
| 首次接入 | 需**批量预热**（快照 + `resolve-*` 结果），建议在产线停机窗口执行 |
| 变更窗口 | 主数据变更生效**不中断生产**（在线批次按锁定版本走完），但**新主数据首用需在 MDS 可用时** |
| 容量影响 | MES 侧需为规则包/快照预留内存（量级 MB–百 MB，取决于订阅范围） |

## 9. 待补 / 后续

- **压测基线**：按 §1.2 的规模做全链路压测，校准 §2.1 指标。
- **分区与归档作业**：历史表/分发表的分区 DDL 与归档 Job（含归档后可查方案）。
- **号池参数调优**：`mds_naming_seq` 分段大小与租户并发关系。
- **多站点部署拓扑**：单实例多站点 vs 每站点独立实例的取舍（与 [multi-site](multi-site-design.md) 联动）。
- **与平台 M4 的对接**：缓存、限流、幂等、mq 由平台能力承载，本文只定义 MDS 侧诉求。
